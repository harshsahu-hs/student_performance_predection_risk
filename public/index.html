A short, honest loop

From assessment to a supportive next step.

The system does not replace academic judgement. It turns four routine data points into an estimate, explains which transparent rules fired, and suggests one or two realistic actions.

Get started
01 · ASSESS

Record what already exists

Attendance, internal marks, weekly study time and previous marks — the same inputs the model was trained on. No extra surveillance.

02 · ESTIMATE

Estimate, then explain

A regression model estimates marks out of 100. Transparent rules add context, and every result carries the prototype badge and a plain-language disclaimer.

03 · SUPPORT

Agree one small step

Recommendations focus on attendance barriers, targeted revision, assignment pacing, participation options and study routines — supportive, never punitive.

Honest by design

What this prototype is — and what it is not.

Early-warning tools can help when they are careful. We state the limits plainly, show real stored metrics, and never present a mock or fabricated result as model output.

Prototype model (UCI dataset)

Trained on 1,044 secondary-school records from Portugal. Accuracy for university students has not yet been validated — treat every estimate as a conversation starter.

Associations, not causes

Attendance and study time are correlated with outcomes in this dataset. That does not mean they cause a mark, and it does not justify a punitive response.

Support, not a label

Risk levels are early-warning signals. They describe the current assessment only, expire with the next one, and are worded to invite support rather than judgement.

Real metrics only

Model comparisons on the analytics page come from the stored evaluation of the trained artifacts. If metrics are missing, the interface says so instead of inventing numbers.

Server-side by default

Secrets stay on the server.

The browser never receives database credentials or model internals. Sessions use a signed JWT in an httpOnly, sameSite cookie; passwords are hashed with bcrypt; login attempts are rate-limited. Every API query is parameterised, and students can only reach their own records.
